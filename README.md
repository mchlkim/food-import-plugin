# 수산물 수입신고 구비서류 조회 플러그인

수입 국가, 생산지역, 품목, 가공 여부를 받아 수산물 수입신고 때 식약처(지방식품의약품안전청)에 제출하는 구비서류와 근거를 돌려준다. 서류의 필수 여부는 공식 자료에서 만든 승인된 규칙으로 판정한다. 근거가 없으면 `UNKNOWN` 으로 답한다.

같은 판정 로직을 CLI, MCP 서버, Agent Skill, Python 함수로 쓸 수 있다.

기준일 2026-11-10. 버전 0.2.0, 규칙 v4(40개). 규칙은 공식 사이트 수집본에서 원문 인용 위치를 확인한 단계(`source_quoted`)이며 실무자 검토 전이다.

0.2.0 에서 달라진 점과 비교 결과는 [docs/spec.md](docs/spec.md) 3절에 있다. 기존 스킬(`seafood-import-docs`)과 비교한 결과를 반영해 위생약정 고시 12개국, 식약처 고시(제9·17·22·23조, 별표 2), 법 제5조, 검사강화 게시물 제목, 조회 전 자동 최신 확인을 넣었다.

## 빠른 시작

```bash
uv venv --python 3.12 .venv && uv pip install -e ".[dev]"
scripts/seafood-import docs "일본 홋카이도산 냉동 가리비 수입신고 서류 알려줘."
```

자세한 설치와 MCP·Skill 연결은 [docs/installation.md](docs/installation.md) 에 있다.

## 조회 예제

```bash
scripts/seafood-import docs "일본 후쿠시마산 수산물 수입 가능한가?"
scripts/seafood-import docs --origin 노르웨이 --product 연어 --state 냉동 --date 2026-12-01
scripts/seafood-import --json docs --origin 일본 --region 홋카이도 --product 가리비 --state 냉동
scripts/seafood-import hygiene 페루
scripts/seafood-import search "복어 검사성적서"
```

현재 규칙으로 나오는 결과 요약:

| 질문 | 수입 가능 여부 | 주요 서류 |
|---|---|---|
| 일본 홋카이도산 냉동 가리비 | 수록된 금지 규칙 해당 없음 | 필수: 방사능 검사증명서(세슘·요오드), 생산지증명서. 조건부: 추가 핵종 검사증명서, 학명 자료 |
| 일본 후쿠시마산 수산물 | 수입금지 | 서류 목록을 싣지 않고 금지 근거를 먼저 표시 |
| 일본산 활 참돔(지역 없음) | 판정 불가 | 생산 도도부현을 되묻는다 |
| 노르웨이산 냉동 연어 | 해당 없음 | 필수: 위생증명서(약정 고시 제5조, 2021-09-23 선적분부터). 조건부: 학명 자료 |
| 페루산 수산물 | 해당 없음 | 필수: 위생증명서 |
| 베트남산 냉동 새우 | 해당 없음 | 필수: 위생증명서 또는 검역증명서. 조건부: 검사명령 이행 성적서(독시싸이클린) |
| 중국산 냉동 오징어 | 해당 없음 | 필수: 위생증명서. 조건부: 야생 수산물이면 야생 수산물 위생증명서 |
| 중국산 활 농어 | 해당 없음 | 위생증명서 미확인(고시가 활수생동물을 적용대상에서 뺌). 조건부: 검량서 |
| 러시아산 냉동 명태 | 해당 없음 | 필수: 수출검사증명서 |
| 인도산 냉동 새우 | 해당 없음 | 위생증명서 미확인(약정 고시를 수록하지 않은 국가) |

모든 조회에 수입신고서와 한글표시 서류(시행규칙 제27조제1항)가 필수로, 제27조제1항제1의2~6호와 식약처 고시 제22·23조 서류가 조건부로 붙는다. 서류마다 근거 조문, 출처 주소, 원문 위치, 인용문이 따라온다.

서류가 아닌 내용은 따로 나온다.

- `prechecks`(신고 전 확인사항): 해외제조업소 등록(법 제5조), 위생약정국 수산물의 포장 표시(식약처 고시 제17조제5항)
- `advisories`(검사강화 게시물): 식품안전나라 검사지시 게시판의 수산물 관련 제목. 승인 절차를 거치지 않는 참고 정보다

조회할 때 마지막 공식 출처 확인이 24시간보다 오래됐으면 먼저 확인한다(`--refresh` 로 항상, `--no-refresh` 로 생략). 확인에는 2분쯤 걸린다. 변경이 감지돼도 판정은 승인된 규칙으로 한다.

출력 형식은 Markdown(기본)과 JSON(`--json`)이다. JSON 의 주요 필드는 `importability`, `documents[].status`, `prechecks`, `advisories`, `freshness_check`, `missing_info`, `assumptions`, `needs_confirmation`, `conflicts`, `data_basis`, `warnings` 다.

## 도구

| 도구(MCP 이름) | CLI | 내용 |
|---|---|---|
| `get_required_documents` | `docs` | 수입 가능 여부와 구비서류 판정 |
| `check_import_restrictions` | `restrictions` | 수입금지·제한 여부 |
| `get_hygiene_certificate_requirements` | `hygiene` | 위생증명서·검사증명서 의무, 수록된 약정국 |
| `search_regulations` | `search` | 수집된 공식 문서 검색(원문 위치·주소 포함) |
| `check_regulation_updates` | `update` | 공식 출처 확인, 변경 시 검토 대기 등록 |
| `get_source_status` | `status` | 출처별 최종 수집, 최신 문서, 실패, 규칙 버전, 검토 대기 |
| `resolve_terms` | `resolve` | 국가·지역·품목 표기 정규화, 통칭 품목 후보 |

운영 명령: `pending`, `show-pending`, `approve`, `reject`, `review`, `versions`, `rollback`, `rules`, `validate`, `history`, `manual-import`.

## 자동 업데이트

```bash
scripts/update_data            # 공식 출처 확인 → 변경이 있으면 검토 대기 등록 (종료 코드 0 변경 없음 / 3 변경 감지 / 2 실패)
scripts/seafood-import show-pending <ID>
scripts/seafood-import approve <ID> --by "<이름>" --verification expert_reviewed
```

변경은 감지만 하고 자동으로 적용하지 않는다. 승인 전까지는 기존 규칙으로 판정하고 결과에 미적용 변경 경고를 붙인다. 수집이나 파싱이 실패해도 승인된 규칙은 그대로다. 스케줄러·CI 연결, 수동 반영, 되돌리기는 [docs/operations.md](docs/operations.md) 에 있다.

## 구현되지 않았거나 공식 검증이 필요한 항목

판정 결과에 영향을 주는 순서로 적는다.

1. **실무자 검토 전이다.** 규칙 v4 는 원문 인용 위치만 확인했다. 관세법인 실무자가 `scripts/seafood-import rules` 로 40개 규칙을 원문과 대조한 뒤 `review` 명령으로 검토 완료를 기록해야 한다. v2~v4 는 이 프로젝트를 만든 에이전트가 "자동 구축, 실무자 검토 전"으로 승인했다. 되돌리려면 `scripts/seafood-import rollback 1 --by "<이름>"` 을 쓴다.
2. **위생증명서를 `필수`로 올린 판단의 근거.** 약정국 12개국의 원물 수산물에 위생증명서(국가에 따라 검사증명서, 수출검사증명서)를 `REQUIRED` 로 답한다. 근거는 시행규칙 제27조제1항제7호와 각 약정 고시의 증명서 조문이다. 다만 고시 적용대상에 드는 수산물이라는 조건이 붙고, 그 조문을 결과에 그대로 인용한다. 개별 품목이 적용대상에 드는지, 등록시설 제품인지는 판정하지 않는다.
3. **약정국 목록은 한정 열거가 아니다.** 국가법령정보센터에 고시명을 등록한 13개 고시만 받는다. 새 약정 고시는 자동으로 찾지 못한다(검색 화면의 내부 요청 형식을 확인하지 못했다). 그래서 12개국 밖의 국가는 `NOT_REQUIRED` 가 아니라 `UNKNOWN` 이다. 일본도 여기에 든다.
4. **활수산물.** 중국 고시는 활수생동물을 적용대상에서 뺀다. 이 경우 위생증명서는 `UNKNOWN` 으로 답하고 수산생물 검역 확인을 안내한다. 검역 요건 자체는 수록하지 않았다.
5. **가공식품의 위생증명서.** 약정 고시의 적용대상은 대부분 단순가공품까지다. 가공식품은 고시의 적용대상 조문을 인용하고 `UNKNOWN` 으로 답한다. 러시아만 고시가 수산가공품을 포함해 `CONDITIONAL` 이다.
6. **일본 "생산지역"의 기준**(어획 해역, 양륙지, 가공지)을 공식 자료에서 확인하지 못했다. 식약처 페이지의 도도부현 구분을 그대로 적용한다.
7. **일본산 원료를 쓴 가공식품**은 제조·생산 지역 기준(구비서류 목록 연번 6)으로만 판정한다. 원료 수산물의 생산지에 수입금지가 적용되는지는 확인 문구를 붙인다.
8. **개별 제품·업체 단위 수입금지와 수입중단**은 규칙에 없다. 결과에 직접 확인하라고 표시한다.
9. **사진 제출 제외 대상 공지**를 수입식품정보마루 공지 검색에서 찾지 못했다. 사진은 조문 단서만 인용해 `CONDITIONAL` 로 답한다. 시행규칙 별표 9 도 수록하지 않았다.
10. **검사강화 게시물은 제목만 싣는다.** 본문, 대상 품목, 기간은 읽지 않는다. 국가 이름으로만 거르므로 다른 품목의 게시물도 함께 나온다.
11. **식약처 외 기관 요건**(관세청 통관, 수산생물 검역, 어획증명 등)은 판정하지 않는다. 해외제조업소가 실제로 등록돼 있는지도 조회하지 않고 조문만 알려 준다.
12. **Open API 는 쓰지 않았다.** 공공데이터포털, 식품안전나라, 법제처 Open API 는 인증키가 필요하다. 법령과 고시는 국가법령정보센터 공개 웹페이지에서 받는다. HS 코드 연결도 없다.
13. **일부 조문은 조건을 요약해 연결했다.** `condition_note` 는 조문을 요약한 것이고 원문은 `quote` 에 함께 실린다.
14. **구비서류 목록 공지 뒤에 올라온 게시물과 서식 변경 공지**(예: "스페인 수산물 위생증명서 추가 변경사항 알림", 2026-08-05)는 제목만 경고로 표시한다.
15. **HWP 첨부 파서가 없다.** PDF 는 글자를 뽑을 수 있는 것만 읽는다. 별표 2 는 PDF 글자에서 두 문장(검량서, 복어 원산지증명서)만 찾아 쓴다.
16. **품목 사전은 34개 묶음**이다. 사전에 없는 품목은 품목 단위 규칙을 판정하지 못한다고 표시한다. 학명 사전은 없다.
17. **자연어 해석은 사전 대조 방식**이다. 복잡한 문장은 에이전트가 해석해 구조화된 값으로 넘기는 것을 전제로 한다.
18. **과거 시점 규정은 없다.** 기준일이 수록된 규정의 시행일 이전이면 판정하지 않고 그 사실을 적는다. 일부개정된 고시는 현행본의 시행일을 시작일로 쓴다.

명세와 원 요청서 대비 변경 사항은 [docs/spec.md](docs/spec.md) 에 있다.
