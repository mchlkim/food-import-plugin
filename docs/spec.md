# 수정본 명세와 구현 계획

원래 요청서(수산물 수입신고 구비서류 조회 에이전트 플러그인 개발)를 검토해 고친 명세다. 이 프로젝트는 이 문서를 기준으로 구현했다. 원문과 달라진 부분만 적는다. 적지 않은 항목은 원문 그대로다.

기준일: 2026-11-10

## 1. 원문에서 고친 결정

### 1.1 판정은 승인된 규칙 스냅샷으로만 한다

원문은 "조회 시 공식 자료로 판정"(7장)과 "검증된 규칙으로 판정"(6·10장)을 함께 요구했다. 다음으로 통일한다.

- 판정 엔진은 승인된 규칙 묶음만 읽는다. 조회할 때 사이트에 접속하지 않는다.
- 조회 결과에는 출처별 최종 확인일을 싣고, 오래됐거나 미적용 변경이 있으면 경고를 붙인다.
- 최신 여부 확인은 `update` 명령(도구 `check_regulation_updates`)이 따로 한다.

### 1.2 `NOT_REQUIRED` 는 한정 열거가 확인됐을 때만 낸다

- 규칙 묶음의 `coverage` 가 주제별로 "출처가 대상을 한정 열거했는지"를 기록한다.
- 한정 열거가 확인된 주제에서 대상에 없으면 `NOT_REQUIRED`, 그렇지 않으면 `UNKNOWN` 이다.
- 현재 위생약정국 목록은 한정 열거가 아니다. 그래서 확인된 6개국 밖의 국가는 `UNKNOWN` 으로 나온다.

### 1.3 규칙에 검증 단계를 둔다

- `source_quoted`: 원문 인용 위치(시트·행, 조문·호, 표 순번)를 확인했다. 실무자 검토 전이다.
- `expert_reviewed`: 실무자가 검토해 승인했다.
- 조회 결과와 응답에 이 단계를 표시한다. 최초 규칙(v1)은 `source_quoted` 다.

### 1.4 자연어 해석은 호스트 에이전트가 한다

- 핵심 엔진은 구조화된 값만 받는다.
- 에이전트(Skill, MCP 클라이언트)가 문장을 해석해 값을 넘긴다.
- CLI 와 `text` 인자에는 사전 대조 방식의 간이 파서를 둔다. LLM API 를 호출하지 않는다.
- 표기 정규화와 통칭 품목 확인용 도구 `resolve_terms` 를 추가했다.

### 1.5 수록 범위를 명시한다

1차 수록 범위는 아래와 같다. 범위 밖은 `UNKNOWN` 이나 "확인하지 않음"으로 답한다.

| 주제 | 수록 내용 | 출처 |
|---|---|---|
| 일반 구비서류 | 시행규칙 제27조제1항 본문과 제1~6호 | 국가법령정보센터 |
| 일본산 수산물 | 수입금지 8개 현, 검사증명서+생산지증명서 8개 지역, 생산지증명서 31개 지역, 추가 핵종 | 수입식품방사능안전정보 |
| 일본산 가공식품 | 13개 도·현, 34개 도·부·현 증명서 | 식약처 구비서류 목록 연번 6 |
| 위생약정 | 공지로 시행을 확인한 6개국(노르웨이, 칠레, 필리핀, 페루, 아르헨티나, 스페인) | 수입식품정보마루 공지 |
| 품목별 | 복어 가공식품, 베트남 쥐치포, 학명 자료 | 식약처 구비서류 목록 연번 3, 9, 19 |
| 검사명령 | 현황표의 수산물 행(참다랑어, 냉동부세, 새우) | 수입식품정보마루 검사명령제 |

### 1.6 원문에 없던 도메인 항목

- 일본 "생산지역"은 식약처 페이지의 도도부현 구분을 그대로 쓴다. 어획 해역·양륙지·가공지 중 무엇이 기준인지는 공식 자료에서 확인하지 못했다. 미검증 항목이다.
- 수출국 정부가 발행하는 증명서 규칙(위생약정)은 수출국으로, 생산지 기준 규칙(일본 방사능)은 원산지로 판정한다. 둘이 다르면 결과에 확인 문구를 붙인다.
- 원물과 가공식품의 경계는 식약처 페이지의 수산물 정의(첨가물·다른 원료 없이 원형을 알아볼 수 있게 단순 절단·가열·숙성·건조·염장)를 따른다.
- 타 기관 요건(관세청, 수산생물 검역 등)과 해외제조업소 등록은 판정하지 않고, 확인하지 않았다는 사실만 결과에 적는다.
- 한글(HWP) 첨부는 파서가 없다. 필요한 문서는 수동 반영한다.

### 1.7 구현 품질 항목

- 규칙에 `effective_from`, `effective_to`, `date_basis`(신고일 또는 선적일)를 둔다.
- 출처를 확인한 지 7일이 넘으면 `STALE_DATA` 경고를 붙인다(`config/settings.yaml`).
- 테스트는 녹화한 실제 응답으로 오프라인 실행한다. 실제 사이트 접속 테스트는 `-m live` 로 분리한다.
- 요청 간격 1.5초, 재시도 2회. robots.txt 는 두 식약처 사이트 모두 제공하지 않는다(요청 시 오류 페이지).
- Open API 키가 없으면 해당 출처를 수집하지 않고 상태에 사유를 표시한다.
- 조회 이력(입력, 규칙 버전, 결과 요약)을 `data/history/queries.jsonl` 에 남긴다.
- 기술 스택은 Python 3.11 이상, 의존성은 openpyxl, PyYAML, (MCP 서버용) mcp 2.x 다.

## 3. 0.2.0: 기존 스킬과 비교한 뒤 고친 것

2026-11-10 에 기존 스킬 `seafood-import-docs`(조회할 때마다 공식 자료를 받아 모델이 판정하는 방식)와 같은 질문 16개로 비교했다. 채점은 이 프로젝트를 만든 에이전트가 했다. 기존 스킬의 답은 별도 에이전트가 스킬 절차대로 한 번 작성한 것이다.

| | 기존 스킬 | 0.1.0 | 0.2.0 |
|---|---|---|---|
| 점수(정답 1, 부분 0.5) | 13 / 16 | 13.5 / 16 | 16 / 16 |
| 틀리거나 놓친 답 | 3 | 0 | 0 |
| 답할 수 있었는데 미확인으로 둔 답 | 0 | 5 | 0 |

0.1.0 이 미확인으로 둔 5건은 중국·러시아·베트남의 위생증명서와 칠레 시행일이었다. 원인은 약정국을 식약처 공지로만 확인한 것이다. 기존 스킬이 놓친 3건은 검사명령 2건(중국 냉동부세, 일본 수출 생식용 참다랑어)과 구비서류 목록 판본(2026.2.5. 판을 최신으로 답함)이다.

0.2.0 에서 고친 것:

| 항목 | 내용 |
|---|---|
| 위생약정국 | 국가법령정보센터에서 약정 고시 13건(12개국) 본문을 받는다. 적용대상 조문과 증명서 조문을 그대로 인용한다. 원물 수산물은 `REQUIRED`, 고시가 뺀 상태(중국 활수생동물)와 가공식품은 `UNKNOWN` |
| 원본 요건 | 식약처 고시 제9조(수출국 정부 발행 원본, 부본·검역기관 확인 사본 포함)를 위생증명서에 붙인다 |
| 조건부 서류 | 식약처 고시 제22조(반송품), 제23조(연구ㆍ조사용), 별표 2(활어·패류 검량서, 복어 원산지증명서) |
| 신고 전 확인사항 | 법 제5조(해외제조업소 등록), 식약처 고시 제17조제5항(약정국 수산물 포장의 등록시설명) |
| 검사강화 게시물 | 식품안전나라 검사지시 게시판 제목. 규칙이 아니라 참고 정보로 붙인다 |
| 최신 확인 | 조회할 때 마지막 확인이 24시간보다 오래됐으면 공식 출처를 먼저 확인한다 |
| 법령 조회 경로 | 제3자 서버나 인증키 없이 국가법령정보센터 공개 페이지를 직접 받는다 |

기존 스킬에 있고 0.2.0 에 없는 것: 사진 제출 제외 대상 목록, 검사강화 게시물 본문, 전자위생증명서·서식 변경 공지의 본문(제목만 경고로 표시), 일본 증명서 발급기관 목록.

16문항은 모두 0.1.0 을 만들 때 쓴 질문이라, 0.2.0 점수는 같은 문항에 맞춰 고친 결과다. 새 질문에서 같은 점수가 나온다는 뜻은 아니다.
